# Agent Modularisation → Connectors — Plan

Agreed 2026-10-17. Goal: every agent is an independently built, self-contained module that an
app adopts by declaring a Gradle dependency — and, on top of that, every adopted agent gets
MCP + REST connectors generated by one core gateway (see CLAUDE.md "External Connectors").
Baseline before refactoring: git tag `pre-modularisation`.

## Target layout

```
settings.gradle                 root build (also auto-includes themes/<name>)
shared-domain/                  :shared-domain        (unchanged for now; step 4 revisits)
os/                             :os                   aggregator — Genesis OS
  agent-sdk/                    :os:agent-sdk         CoreAgent + AgentCustomOption (pure Java)
  runtime/                      :os:runtime           was brain-engine-core
  agents/<id>/                  :os:agents:<id>       one module per OS agent
  app/                          :os:app               was genesis-os (bootJar)
brands/                         :brands               aggregator — Genesis Brands (step 4)
  domain/                       :brands:domain        Engagement, Brand, orchestration
  agents/<id>/                  :brands:agents:<id>   copy, visual-identity, logo, playbook, brand-book
  consultant-ext/               :brands:consultant-ext  Consultant extension (SPI impls + view ext)
  app/                          :brands:app           was genesis-brands (bootJar)
themes/<name>/                  unchanged
```

Jar names are derived from the project path (`os-runtime`, `os-agents-summarizer`, …) so no two
modules ever collide inside a fat jar. Java packages stay `ai.genesisbrands.*`.

## Dependency rules

```
os:agent-sdk  ← os:runtime ← os:app
     ↑              ↑         ↑
os:agents:<id> ─────┘(compileOnly, only when it needs runtime services)
                              │
brands:app → os:runtime + adopted os:agents:<id> + brands:domain + brands:agents:<id>
```

- An agent module depends on `os:agent-sdk` (and `os:runtime` compileOnly only if it needs
  runtime services). The runtime never depends on any agent.
- **Adoption = dependency.** An app has exactly the agents it declares. No agent is pulled in
  implicitly.
- `ModuleOrigin.isCore()` = "class comes from any `os` module".

## What an agent module contains (its whole contract)

```
os/agents/<id>/
  build.gradle
  src/main/java/.../<Id>CoreAgent.java        metadata (CoreAgent bean, component-scanned)
  src/main/java/...                           its own logic, if it isn't a generic agent
  src/main/resources/agents/<id>/agent.yml    default config: model, max-tokens, rag, …
  src/main/resources/agents/<id>/system.md    system prompt (found by convention)
  src/main/resources/static/agent-views/<id>/ playground.js/.css, live.js/.css
```

- **Config defaults live with the agent.** The runtime loads every `agents/*/agent.yml` on
  the classpath as the lowest-priority property source under `genesis.agents.<id>.*`. An app's
  `application.yml` sets only what it changes (extend, don't copy), and the admin layer
  (step 7) sits above both.
- **Prompt by convention:** `agents/<id>/system.md` unless `system-prompt` overrides it.
- **Views by convention:** unchanged `/agent-views/<id>/{live,playground}.js`, now served from
  the agent's own jar.

4. **Brands aggregator.** DONE. Move genesis-brands → `brands/app`, extract `brands/domain`, then the

   Brands still adopts the 6 OS utility agents (behaviour unchanged; dropping them is a one-line
   Gradle change per agent — product decision for the user).
5. **Connector gateway.** DONE. In `os/runtime` (or `os/connectors`):
   - **Agent connectors:** MCP tools and REST endpoints generated from `AgentCatalogService`
     for each adopted, connector-enabled agent. Customer API keys/OAuth resolve to a
     tenant + client server-side. `requireAvailableForLiveView` plus a new connector flag.
     SLOT agents use start/poll/approve.
   - **Brain connector:** Layer 1 + Layer 2 retrieval only.
   - **Platform connector:** admin operations collected from the admin APIs plus an SPI for
     tenant-only operations, with its own admin credentials and audit trail.
   *Done as:* a new `os/connectors` module that both apps adopt. Connector keys are hashed
   bearer keys: `gbc_…` (CLIENT, bound to one client user, which the client can self-issue at
   `/api/client/connector-keys`) and `gbp_…` (PLATFORM, admin-issued at
   `/api/admin/connector-keys`). REST is under `/api/connect/{agents,brain,platform}` and MCP
   (stateless JSON-RPC over POST) under `/mcp/{agents,agents/<id>,brain,platform}`.
   - **Agent modes:** JOB through the `ConnectorJobProvider` SPI (Genesis Brands:
     `EngagementConnectorJobProvider` → approval-gated regeneration); CHAT through
     `ConnectorChatProvider` (Consultant) or generic chat; GENERATE for generic single-shot
     agents.
   - **Gating:** the new `availableForConnectors` flag (agents admin, default off) AND live-view.
   - **Brain:** layers come from `genesis.connectors.brain.layers`, default `layer1,layer2`.
     **Pending:** Layer 2 is cross-client and not yet anonymised on ingest. That has to land
     before external customers use the Brain connector; until then, set the property to `layer1`.
   - **Platform:** operations are collected from the handler mappings and narrowed by
     `PlatformOperationFilter` beans (the tenant SPI). They are invoked via an admin loopback
     call, and every call is written to `platform_audit_log`.
   - **Deferred:** OAuth (API keys only for now) and a key-management UI.
   - Also fixed: library modules weren't compiled with `-parameters`, which broke unnamed
     `@PathVariable`s in module controllers (now set for all modules in the root build).
6. **Theme + views (#3, #6, #7).** DONE. Replace hardcoded hex with theme tokens in brands views and
   `_shared`, and add the missing playground views.
   - `--av-*` tokens live in `os/runtime` `agent-views/_shared/tokens.css` (light defaults). Each
     host maps them to its theme; `playground.html` maps them to dark `--theme-*` values. All
     agent-view CSS uses only tokens. Brands live views share `_shared/regenerate.css`.
   - Every agent now has its own `playground.js`.
     - The 5 SLOT agents mount `brands/app` `_shared/slotPlayground.js`, which handles the
       questionnaire, brief, options, runs, history, audit and feedback. Each agent supplies only
       its output renderers and source runs.
     - Consultant's view embeds `/console.html`.
   - `playground.html` is now chrome only (2325 → ~480 lines). It lists agents, pages flows, and
     mounts the selected agent's view via `mountAgentPlaygroundView`. `?agentId=&session=` deep
     links pass `ctx.sessionId` through.
   - Left for the widget pass: hex in the `dashboardAgents` panel/cards and in `dashboardCatalog`.
7. **Admin config (#2, #4, #9).** DONE. Admin-editable agent settings layered over `agent.yml` and
   app overrides, plus a view extension mechanism (extend a base view, not a same-path copy).
   - **Three config layers**, lowest first: `agents/<key>/agent.yml`, the app's `application.yml`,
     then admin overrides in the `agent_settings_overrides` table (one row per config key; null
     fields inherit). `AgentProperties.get(key)` and `systemPrompt(key)` return the merged result
     and are called per request, so changes apply without a restart. `AgentSettingsOverrideStore`
     caches overrides for 10s; other replicas see a change within that.
   - Agents no longer load prompts in constructors; every agent, evaluator and the generic
     chat/single-shot services call `agentProperties.systemPrompt(key)`.
   - **Config keys are not agent ids.** A key belongs to the agent with the longest matching id
     (`copy` owns `copy` and `copy-evaluator`; `logo` owns `logo-dalle`, `logo-svg`, …).
   - Admin API: `GET /api/admin/agents/{id}/settings`, `PUT|DELETE .../settings/{key}`. Editable:
     model, max tokens, max iterations, knowledge retrieval on/off, top-k and the system prompt.
     The agents admin page has a Settings panel per card.
   - Consultant's config moved from `genesis.consultant.system-prompt` to
     `genesis.agents.consultant.*` with its own `agent.yml`; `ConsultantService` now honours
     model, max tokens and RAG settings from it.
   - **View extensions:** an `AgentViewExtension` bean (agent-sdk) names an agent, a view and a
     module. `GET /agent-views/extensions.json` publishes them; `agent-loader.js` chains each
     extension's `mount(container, agent, ctx, base)` over the base view. Brands' Consultant live
     view is now `consultant/ext/brands-live.js` extending the core view.
     `AgentViewPathsTest` fails the build if any `static/agent-views/**` path exists twice on the
     classpath.

Every step: build, run tests, smoke-test locally, deploy both apps, check production, commit.
